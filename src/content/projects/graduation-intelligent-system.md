## 💡 课题背景与研发初衷

在传统中小型企业的日常运营中，供应链各个业务环节普遍面临**信息孤岛严重、供应商资质监管难、采购审批流程脱节、库存周转低效、订单履约不可视**等管理痛点。

本课题设计并实现了一套**面向中小型企业的前后端分离供应链管理平台（Supply Chain
Management,
SCM）**。系统核心覆盖用户与权限管理、供应商管理、采购管理、库存管理、订单管理及报表统计等全流程模块，实现了供应商准入审核、采购单全流程管控、库存实时监控与智能预警、销售订单全链路跟踪及多维度数据统计分析，为企业提供数字化、规范化的供应链管理全套解决方案，全面提升管理效率与决策科学性。

## 🏛️ 总体技术选型与架构设计

系统严格遵循 **RESTful 规范** 与
**组件化解耦思想**，采用业界主流的高可用企业级前后端分离架构：

| 架构分层           | 核心技术栈                                   | 核心职责与关键实现                                              |
| :----------------- | :------------------------------------------- | :-------------------------------------------------------------- |
| **🖥️ 表现层 (UI)** | `React 18` · `TypeScript` · `Ant Design Pro` | 页面组件化解耦开发、响应式数据交互大屏 (`ECharts`)              |
| **🔐 安全鉴权层**  | `Spring Security` · `JWT` · `Redis`          | 无状态 Token 签发、黑名单注销、RBAC 细粒度权限拦截与审计日志    |
| **⚙️ 业务逻辑层**  | `Spring Boot 3` · `Spring MVC`               | 核心供应链业务流转、全局统一异常处理 (`GlobalExceptionHandler`) |
| **💾 持久数据层**  | `MyBatis-Plus` · `MySQL 8.0`                 | 数据库 CRUD 操作、分页插件、逻辑删除与行级乐观锁控制            |
| **⚡ 缓存与并发**  | `Redis 7.x`                                  | 高频商品数据缓存、Token 状态维护、高并发分布式防重提交锁        |
| **☁️ 基础设施层**  | `阿里云 OSS` · `EasyExcel / POI`             | 供应商资质文件云存储、大批量数据流式异步报表批量导出            |

## ✨ 核心功能模块与业务实现

### 1. 用户与权限管理中枢 (RBAC)

- **安全鉴权与 Token 管理**：整合 `Spring Security` 与 `JWT`
  建立无状态认证机制，利用 `Redis` 维护在线用户 Token、过期黑名单与双重校验；
- **细粒度动态授权**：构建“用户-角色-权限”模型（RBAC），实现菜单、路由与操作按钮级别的权限控制；全面记录用户登录与核心业务操作审计日志。

### 2. 供应商全生命周期管理

- **信息档案与资质管理**：建立供应商完整电子台账，集成 OSS
  实现营业执照等资质文件的异步上传与合规审核；
- **多维度评分与分类查询**：基于供货交期、质量合格率与合作信用建立量化评分模型，支持分类分级与动态分页条件查询。

### 3. 采购管理全流程管控

- **业务流程闭环**：打通“采购申请 -> 部门多级审核 -> 采购单下达 -> 财务复核 ->
  入库协同”完整状态链；
- **状态追踪与报表导出**：实时跟踪采购单执行状态与履约进度，支持采购单据的批量
  Excel 格式化导出。

### 4. 实时库存监控与智能预警

- **商品与出入库事务操作**：精细化管理商品
  SKU，严格保证采购入库、销售出库、盘点调拨等业务的数据库事务一致性（ACID），完整追溯台账变动流水；
- **安全库存动态预警**：建立库存上限/下限警戒水位监控，低于阈值时即时触发采购补货预警提醒，避免断货或呆滞积压。

### 5. 销售订单管理与履约追踪

- **库存联动与订单流转**：实现销售订单创建时的库存原子性预占与扣减校验，并实时跟踪订单履约与物流分发状态；
- **异常退换货处理**：支持订单取消、退货退款自动化原路回滚库存，保障账实相符。

### 6. 多维度报表统计与数据可视化

- **ECharts 动态可视化大屏**：直观展示月度收支走势、热销商品 Top
  榜、各品类库存占比环形图及供应商履约率雷达图；
- **多条件筛选与经营分析**：支持按时间跨度、部门、品类的组合筛选计算与报表一键导出。

### 7. 系统基础通用配置

- **数据字典与系统参数**：统一管理业务枚举（商品类别、单位、审批状态等），支持全局系统运行参数的热更新与客户档案维护。

## 🛠️ 关键攻关难点与技术解决方案

> ### 难点 1：并发下单与出入库时的库存超卖与数据强一致性
>
> **问题**：在高并发下单或多仓管员同时操作出入库单据时，传统数据库并发查询与更新极易引发库存负数超卖或脏读。
>
> **解决方案**：引入 **Redis 分布式锁 + 数据库乐观锁 (Version
> 版本号机制)**；在数据库底层运用
> `update ... set stock = stock - count where stock >= count`
> 的原子扣减条件，严格杜绝库存超卖与并发冲突。

> ### 难点 2：复杂多级采购审批流的状态流转与逻辑解耦
>
> **问题**：采购单状态分支繁多（草稿、待初审、待复审、已驳回、采购中、已完成），大量嵌套
> `if-else` 极易导致状态死锁与扩展困难。
>
> **解决方案**：采用**状态模式 (State Pattern)**
> 重构审批状态机，将各状态流转的前置校验与后置事件（如消息通知、库存预占）独立封装，使审批流程具备高度的可配置性与可回溯性。

> ### 难点 3：多表海量流水统计报表查询慢与导出内存溢出 (OOM)
>
> **问题**：多表深度关联（采购、销售、出入库、商品台账）查询历史报表时响应迟缓，大批量数据导出容易造成
> JVM 内存突增。
>
> **解决方案**：基于复合索引对慢 SQL 进行深度调优，并对高频汇总数据在 Redis
> 中构建定期聚合缓存；文件导出端采用流式分批读取方案，将内存占用稳定控制在极低水平。
